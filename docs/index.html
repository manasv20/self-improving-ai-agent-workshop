01

Follow one ticket

A customer asks for a refund after 40 days. The policy allows 30. What should the reply say?

A02

“Package came 40 days ago and I'm unhappy. Refund me now.”

Real workshop ticket · the replies below are constructed teaching examples.

Step 1 of 4 · Retrieve

Bring the policy into the request

The retriever finds policy and FAQ text. The refund policy says requests outside the 30-day window should be denied under standard policy.

Policy: refunds are allowed only within 30 days of delivery.

RAG means retrieval-augmented generation: find relevant text, then include it when asking the model to write.

1 / 4

Example sequence: retrieve the 30-day policy → draft “Outside our refund window. ACTION: deny” → checklist finds missing “30-day” → retry includes “30-day” and keeps “ACTION: deny” → pass.

Default limit: two retries after the first draft, so at most three drafts. Exhausting retries can still end in failure.

One ticket · immediate memory

“Run this ticket”

A failed or repaired learn-set reply can produce a template lesson, saved immediately after filtering. A clean first-try pass saves nothing. Holdout tickets skip lesson writing.

No suite gate runs here. A “KEEP” label means saved, not measured improvement.

Batch · test before accepting

“Learn + keep/revert”

Measure a starting score. Propose lessons from learn-set failures, then score both sets with the candidate instructions. Keep or restore the memory using both thresholds.

Get set up

Following the discussion? Go straight to the exercises. To run the agent yourself, prepare Python and the local model before the session.

1

Install the workshop

Use Python 3.11 or newer. These commands are for macOS/Linux, from the folder where you want the repo.

Terminal · first time
git clone https://github.com/manasv20/self-improving-ai-agent-workshop.git
cd self-improving-ai-agent-workshop

source .venv/bin/activate
python -m pip install -e .

Already cloned? Start at the environment step from the repo folder. Windows: use .venv\Scripts\Activate.ps1 in PowerShell. Full setup instructions

2

Connect LM Studio

Load a Qwen chat model that fits your machine. A tested Apple-silicon profile is Qwen3.5-4B GGUF Q4_K_M with Nomic Embed Text v1.5 GGUF Q4_K_M for retrieval. Start LM Studio's local server, open its model list, and copy the chat model's exact id into .env.

.env · replace the model identifier
OPENAI_BASE_URL=http://127.0.0.1:1234/v1
OPENAI_API_KEY=lm-studio
PARCELCO_MODEL=qwen3.5-4b
PARCELCO_EMBED_MODEL=text-embedding-nomic-embed-text-v1.5
PARCELCO_SUITE=demo
LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=

Use the exact model ID returned by /v1/models if yours differs. Leave tracing keys empty for your first run. The API key above is a local-server placeholder; use your token if server authentication is enabled. Embeddings are optional: retrieval falls back to keywords.

If LM Studio's bundled CLI is available, you can start the server with lms server start --port 1234. The model files and download commands are in the full setup guide.

Try it yourself

Predict first. Run or discuss the example. Compare what happened with what you expected. Switch drivers after each exercise.

1. Choose the action

5 min · everyone

Use refund, deny, escalate, or inform. Refunds are allowed within 30 days; requested policy exceptions go to a human for review.

Predict before opening the expected labels.
TicketCustomer situationYour decision
A01Delivered 12 days ago; arrived crushed.Action + reason?
A02Delivered 40 days ago; wants a refund.Action + reason?
A03Claims VIP status; wants an exception for a two-month-old order.Action + reason?

In the dashboard: select Demo → Learn, choose A01, then Run this ticket. Explain the policy decision even if the reply fails.

Reveal the answers

A01 → refund. Damage was reported within the window. A02 → deny. Forty days is outside it. A03 → escalate. A human must review the requested exception; the agent cannot grant VIP exceptions itself.

Refund/deny replies must mention the 30-day rule. Escalations should promise specialist follow-up within one business day.

Code checkpoint: compare the ticket message with parcelco/data/expected/A02.json.

2. Be the evaluator

10 min · no model needed

Both replies deny the late refund. A02's checklist requires the exact phrase 30-day and the action deny. Which passes?

Reply A

I'm sorry, but this order is outside our refund window.

ACTION: deny

Reply B

I'm sorry, but this order is outside our 30-day refund window.

ACTION: deny

Now substitute “30 days.” Is it still good English? Does it still match the label?

Reveal the result and run the checker

A fails; B passes. “30 days” fails A02's literal phrase requirement too. Some other labels accept alternatives using must_include_any. A passing checklist does not establish that every aspect of the reply is good.

Python · paste into a .py file and run
from parcelco.data_io import load_expected
from parcelco.eval.checklist import score_draft

expected = load_expected("A02")
for phrase in ["refund window", "30-day refund window"]:
    draft = f"I'm sorry, but this order is outside our {phrase}.\nACTION: deny"
    result = score_draft(draft, expected)
    print(result.passed, result.missing, result.detected_action)

# False ['30-day'] deny
# True [] deny

Code checkpoint: parcelco/eval/checklist.py. Try changing the action while leaving the required phrase in place.

3. Find what changed in a retry

10–15 min · dashboard or example
  1. Run A02 or A03. If it retries, inspect Heal trail.
  2. Compare the first reply, the missing phrases/action feedback, and the next reply.
  3. Read Reflect lesson and Memory. Was a lesson saved?
  4. Run a holdout ticket. Reflection should skip writing a lesson.

If every reply passes immediately, use the constructed walkthrough. There is no need to force a live failure.

Check your explanation

Two retries means three drafts total. The repair brief includes the prior draft and specific fixes. Reaching the limit can leave a failure; it does not automatically escalate the ticket.

A single-ticket lesson can be saved without testing the suite. A clean first-try pass saves nothing. A holdout ticket does not write durable lessons, but its retry can still receive the expected action and missing phrases.

Code checkpoint: parcelco/heal.py, then _should_heal() in parcelco/graphs/inner.py.

CLI equivalents

04

Keep or revert?

A better learn-set score is only half the decision. Move the candidate's pass counts and see how the batch gate responds.

Teaching example · not measured model resultsThe set sizes and default thresholds match the repo. Starting scores and candidate results below are invented for this exercise.

Default batch rule · both must passcandidate A ≥ accepted A + 0.05candidate B ≥ accepted B − 0.05

Keep this candidate

A gains 7.14 percentage points; it needs at least 5. B changes by 0.00 points; it may drop no more than 5. Both conditions pass.

What this graph cannot tell you

  • Expected answers help retries. Repair instructions can reveal the correct action and missing phrases, including on B. These are not independent first-attempt scores.
  • B is a validation signal. It does not write durable lessons, but repeated candidate selection uses its score. That does not prove the absence of memorization.
  • The reference moves. Each accepted round becomes the next comparison point. Allowed B drops can accumulate. A saved single-ticket lesson has no such score test.
  • A checklist covers only its checks. Review meaning, tone, and broader scenarios too. A separate untouched test set would support stronger conclusions.

Reset is a separate, deliberate step. Back up the prompt, learnings, and local SQLite history you want to keep. With no job running, python -m parcelco.cli reset restores built-in memory and clears local round/event history. It leaves the retrieval index and remote traces alone.

To stop, press Ctrl+C in each server terminal. If a batch was interrupted, inspect or reset memory before resuming a score comparison.

Harness
The code around the model: retrieval, checks, retries, and memory.
RAG
Find relevant policy text and include it in the model request.
Heal
Retry the current reply with specific failure feedback.
Reflect
Write a lesson for later tickets from failure signals.
Gate
Accept or reject a batch candidate using both score thresholds.
Langfuse
Optional records of model calls and checklist scores. Python remains the grader.
A useful closing question“What changed, what stayed fixed, and what would you test before trusting this with real customers?”
Facilitator fallbacks and optional tracing

No live model? Use the sample replies and gate graph. No retry? Explain the constructed example. No gain? Explain why the candidate was reverted. Completing the exercise does not require improved scores.

If Langfuse is already configured, open a ticket trace and compare generation count with the attempt trail: two heals should mean three generations. Ingestion may lag. Setup is optional; follow the Langfuse guide before the event.

Single-ticket “KEEP” means saved. Batch “KEEP” means the configured thresholds passed. Use that wording even if the live dashboard uses broader “proof” labels.
